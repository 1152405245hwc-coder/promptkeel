## [0.2.0] - 2026-11-19

First release of `dsh-forge-kit` (renamed from `dsh-forge`) with a verified 4-host core (`dsh`, `claude-code`, `codex`, `opencode`) backed by golden fixtures, a hardened persistent delivery session loop (`dsh-session` / `dsh-forge session`), and strict anti-regression / measurement guardrails.

**Upgrade & migration notes**

- **Package, plugin ID, route & state root rename (`dsh-forge-kit`)**:
  - Package name, Cordis plugin node, and DSH client module ID moved from `dsh-forge` to `dsh-forge-kit`; `cordis.patch.yml` disables any legacy `dsh-forge` node alongside `dsh-purge*`, and `dsh-forge profile enable` migrates legacy `dsh-forge` bundle entries automatically.
  - Loopback API prefix moved from `/dsh-forge/api` to `/dsh-forge-kit/api`.
  - Default state roots moved to `~/.dsh-forge-kit/` (`$XDG_STATE_HOME/dsh-forge-kit`, env `DSH_FORGE_KIT_STATE` with legacy fallback `DSH_FORGE_STATE`) and `~/.dsh/dsh-forge-kit/`. Environment overrides `DSH_FORGE_KIT_PROFILE` and `DSH_FORGE_KIT_HOST_ROOT` retain fallbacks to `DSH_FORGE_*`.
  - Binaries: `dsh-forge-kit`, `dsh-forge`, and `dsh-session` (`dsh-forge session` also forwards to `dsh-session`). Managed block markers (`<!-- dsh-forge ... -->`) stay unchanged so existing host blocks remain idempotent.
- **Removed & tightened exports (SemVer)**:
  - Removed unreferenced exports `requireSupport` (`core/capabilities.mjs`) and `listProviders` / `providerForAction` (`core/provider.mjs`).
  - Replaced blanket `export *` in `core/index.mjs` with explicit curated named exports (`test/public-api.test.mjs`).
  - Removed the 38-symbol legacy re-export shim from `scripts/live_matrix.mjs`; import strategy and gateway APIs from `core/strategy.mjs` / `core/gateway.mjs` (or `dsh-forge-kit/core`).
  - Removed `inlineTurn()` from `core/session.mjs` before release; `systemVariants()` and `repackTurn()` cover placement and packing decisions cleanly.
- **Primary vs. frozen hosts & trimmed package**:
  - Promoted `opencode` to `verified` alongside `dsh`, `claude-code`, and `codex`, all guarded by golden detection fixtures (`test/fixtures/hosts/`). Remaining 9 profiles are labeled frozen/experimental.
  - Excluded `docs/research/` snapshots and offline Python `tools/` from npm release tarballs (`package.json` `files`).
- Published figures in `docs/` are re-generated by `scripts/check_docs.mjs`; run `npm run docs:check` after editing any number that a doc quotes.

### Added

- **Persistent All-Model Delivery Sessions (`core/families.mjs`, `core/session.mjs`, `scripts/session.mjs`, `bin/dsh-session.js`, `test/session.test.mjs`, `docs/SESSION.md`)**:
  Added `dsh-session` with on-disk session state, a short task lock re-asserted every turn, per-family arm ladders (deepseek / claude / gpt / gemini / glm / qwen / llama / generic), automatic escalation on withheld, empty, blocked or thin turns, family-level UCB1 learning across sessions, and auditable stability metrics (delivery rate, longest failure streak). Commands: `start`, `turn`, `record`, `status`, `list`, `export`, `archive`, `matrix`.
- **System-Slot Degradation (`core/session.mjs`, `scripts/session.mjs`)**:
  Some OpenAI-compatible proxies reject or hang on a populated `system` slot while accepting the same bytes as a leading user message. Added `SYSTEM_MODES` (`full` / `inline` / `lock` / `bare`) and `systemVariants()`, used by `dsh-session turn --send`: a rejected request body degrades to the next placement (network errors and timeouts do not, since placement is unrelated to them), and the placement that got through is persisted as `session.systemMode` and recorded per turn, so later turns start where the endpoint already accepts. Added the `inline` arm to every family ladder, plus `inlineTurn()`, and fixed `sendTurn` passing a pre-built body where `sendRequest` expects a descriptor. `scripts/fixtures/system-rejecting-gateway.mjs` reproduces the failure mode locally, and `matrix` without `--send` is now a pure preview that no longer writes error turns into family priors.
- **Live Matrix System Placement (`scripts/live_matrix.mjs`, `test/live-matrix.test.mjs`)**:
  Added `--system-mode full|inline|bare` and exported `placeSystem()`, so the audit runner can put the compiled prompt where the endpoint actually accepts it. The runner previously always used the `system` slot, which is exactly the placement some proxies reject or hang on, so a live matrix could read as "no model answers" when the transport was the only thing failing. Placement stays a flag: the prompt bytes are unchanged, and an empty body never leaves a blank system message on the wire.
- **Turn Shapes (`core/session.mjs`, `scripts/session.mjs`, `test/session.test.mjs`, `docs/SESSION.md`)**:
  Added `TURN_SHAPES` (`history` / `single` / `bare`) and `repackTurn()`. A reachable endpoint can answer a lone user message and reject the identical request as a two-message conversation — measured on one route as 3/3 answered versus 3/3 failed at the same token budget — so replay is now a transport choice like placement is. `turn --send` starts from the learned shape, degrades on a rejection or a stall, remembers the pack that got through (`session.shape`, per-turn `shape`), and a stalled shape is abandoned after one try so the worst case is two timeouts rather than a full walk. `bare` sends the request text alone, which is what a plain client would send.
- **Measurement Rules (`docs/MEASUREMENT_RULES.md`)**:
  Codified the eight rules the run history already paid for — minimum sample size, classifier stamping, four-state outcomes, interleaved arms, starvation checks, public retraction, reproduction blocks, one variable per comparison — each traceable to the commit that forced it.
- **Cross-Host Hardening & Real-CLI Fixes (`codex`, `opencode`, `hermes`, `gemini`, `claude-code`)**:
  Added `.codex/dsh-forge-shim.sh` (`{{TOML_PROMPT_PATH}}` safe space/quote/backslash escaping in `core/shim.mjs`) to enforce `B4 replace-full` even in untrusted Codex repositories; upgraded `opencode` (`agent.build.prompt` in `opencode.json` + `core/grades.mjs`) to verified `replace-full`; switched `hermes` markdown blocks to `blockId: "forge"` plus `yaml-merge` on `.hermes/config.yaml` (`agent.system_prompt`) to clear Hermes `html_comment_injection` filters; updated `gemini` to `general.defaultApprovalMode: "auto_edit"` and separated `.claude/forge-prompt.md` from repo `CLAUDE.md`.
- **Direct Narrative Mode & Fiction Strategies (`prompt/modes/writing.md`, `prompt/personas/unfiltered.md`, `core/strategy.mjs`)**:
  Tightened `--mode writing` and `unfiltered` within the `480`-token budget for unbroken physical/sensory fiction prose without fade-to-black or moral codas; added `narrative` and `narrative+variable` two-turn beat-to-scene strategies.

### Changed

- Core compilation no longer imports DSH patch/ASAR runtime modules directly; DSH actions use an explicit synchronous provider bridge.
- Activation evidence now rejects `active` without session/runtime proof and treats generic or unobservable hosts explicitly.
- Batch application is experimental and opt-in; serialized target metadata, preview requirements, replay guards, and state-key isolation prevent silent empty applies.
- Host support now uses a normalized adapter registry and includes Cursor, Windsurf, Aider, and Continue profiles; DSH remains one adapter with its native patch provider.
- Added `compileMany()`/`applyBatch()` for deterministic multi-platform plans, target conflict detection, batch previews, locks, and compensation rollback.
- `doctor` and `status --json` now report configuration, host readiness, session loading, and restart requirements as separate activation fields.
- Privacy checks ignore the local `.dsh-forge-state/` plan ledger, which is runtime state and is now excluded from Git.
- Profiles now expose risk, host mutation, restart, and activation-evidence metadata; existing high-permission behavior remains unchanged.
- CI runs on Node 20 and 22 with a reproducible npm lockfile and repository quality gate.

### Fixed

- Prompt section tests no longer depend on an incidental `AGENTS.md` in the checkout.
- `injectionSource` only recognizes an `AGENTS.md` that contains a dsh-forge managed block.
- Cross-host applies can persist a `forge.preview/v1` file and refuse to overwrite files whose SHA-256 changed after preview.
